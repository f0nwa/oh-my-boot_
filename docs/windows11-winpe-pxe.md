# Windows 11 x64: первая проверка WinPE

На сервере найден ISO `26100.5067.250818-2008.GE_RELEASE_SVC_PROD3_CLIENTPRO_OEMRET_X64FRE_RU-RU.ISO` в подключённой SMB-папке. Для начальной загрузки из него скопирован `sources/boot.wim` в `/srv/pxe/tftp/windows11/boot.wim`. Размер — 698 729 786 байт, SHA-256 — `33f30dccd7479ddb31fc6cd692ca7f420eaee5af388f8ecc8fa3f9524a31d4a4`; `cmp` подтвердил совпадение с файлом в ISO. Boot отдаёт его по `/assets/windows11/boot.wim`: HTTP HEAD 200, запрос первых 1024 байт — 206. Для загрузки используется уже закреплённый и проверенный `wimboot` 2.9.0 из [профиля Windows 10](windows-winpe-pxe.md).

Админка предлагает отдельный пункт **Windows 11 x64 — запуск WinPE**. Его публикация выполняется вручную через страницу **Меню**, сохраняя выбранные Ubuntu и Windows 10. Замена бинарного файла Control не меняет действующее опубликованное меню; его SHA-256 до и после замены остался `c3730b5ceed31bc218b7ab9cd42c1f3fc6e4d944e739117a85b2ff6a8d2f676c`. Предыдущий бинарный файл сохранён в `/var/backups/pxe-platform-pre-win11-20261016/pxe-control`.

Пользователь опубликовал пункт Windows 11; активное меню содержит Ubuntu, Windows 10 и Windows 11 (SHA-256 `7120f842b72b1f2dda998c79f1c9385c21c1461f7eacb7f82d96d5ec51729b89`). На ВМ 112 в OVMF окно установки Windows 11 появилось как с выключенным, так и с включённым Secure Boot. Установку на диск не запускали.

## Полные файлы установки

Содержимое ISO скопировано из подключения только для чтения в `/srv/pxe/installers/windows11` (1054 файла). Сверка `cmp` подтвердила совпадение `sources/boot.wim` и `sources/install.wim` с ISO; размер `install.wim` — 8 693 893 898 байт. Отдельная папка `\\10.30.0.10\windows11` задана в [`deploy/samba/smb.conf`](../deploy/samba/smb.conf) с теми же ограничениями, что и Windows 10: только `10.30.0.0/24`, вход `pxe-install`, обязательная подпись SMB и чтение без записи. Пароль тот же, что для Windows 10; пароль исходного хранилища клиенту не передаётся.

На сервере `testparm` принял новую конфигурацию. `smbclient` от имени `pxe-install` прочитал `setup.exe` побайтово, увидел `install.wim`, но не смог создать каталог; анонимный вход отклонён. Шара Windows 10 после изменения осталась доступна. В WinPE с включённым Secure Boot пользователь выполнил `wpeutil InitializeNetwork`, подключил `\\10.30.0.10\windows11` и подтвердил, что `Z:\sources\install.wim` виден.

Сразу после запуска `Z:\setup.exe` установщик запросил драйвер для обнаружения оборудования. В этом Windows 11 WinPE команда `diskpart` → `rescan` → `list disk` **не показала** 32-ГБ диск ВМ 112, подключённый как `scsi0` через VirtIO SCSI single. Пользователь выключил ВМ, отсоединил диск без удаления его образа и подключил тот же образ как `sata0`. После новой загрузки WinPE и `rescan` команда `list disk` показала диск. Это подтверждает проблему обнаружения диска через VirtIO SCSI в текущем Windows 11 WinPE. [Proxmox описывает такой способ смены шины](https://pve.proxmox.com/wiki/Migrate_to_Proxmox_VE). Размер диска доведён до 64 ГБ, что соответствует [минимуму Windows 11](https://learn.microsoft.com/en-us/windows/whats-new/windows-11-requirements), но запрос драйвера остался.

Подробный журнал `X:\$WINDOWS.~BT\Sources\Panther\setupact.log` дал точную причину текущего экрана: `Driver: Found install image at [(null)]`, `Found Media path at [(null)]`, `Unable to find media`. В том же журнале Setup видит `QEMU HARDDISK` размером 68 719 476 736 байт и шину `Serial ATA`. Значит, сообщение о драйвере здесь относится к отсутствующему **источнику установки**, а не к обнаружению SATA-диска. Автоматический Setup запускается до ручного подключения `Z:`. На сервере есть исполняемый `sources/setup.exe`, рекомендованный [Microsoft для запуска из WinPE](https://learn.microsoft.com/en-us/windows-hardware/manufacture/desktop/windows-setup-supported-platforms-and-cross-platform-deployments?view=windows-11); попытка запустить его при уже открытом Setup сразу возвращает командную строку. `setuperr.log` содержит также ошибки MOUPG `0x80072EE7`, `0x80070490` и `0x80070002`, но журнал не связывает их с экраном запроса драйвера. Диск не очищали и установку не начинали.

Для отката отключить `smbd.service`, восстановить `/var/backups/pxe-platform-pre-win11-smb-20261016/smb.conf` в `/etc/samba/smb.conf` и запустить `smbd.service`. Старую папку Windows 10 откат не затрагивает. Полную копию `/srv/pxe/installers/windows11` удалять только после завершения клиентских проверок.

## Автоматический старт из исходного ISO: лабораторная проверка 16.10.2026

Подготовлен первый вариант запуска Windows 11 без команд в WinPE. Исходный ISO остаётся на подключённой SMB-шаре Synology и монтируется на PXE-сервере как UDF только для чтения в `/mnt/pxe-platform-iso/windows11`. Новая Samba-папка `\\10.30.0.10\windows11iso` выдаёт файлы непосредственно из этого монтирования; полная копия ISO для нового пути не создавалась. Старая локальная копия `/srv/pxe/installers/windows11` пока оставлена для отката.

Отдельный пользователь `pxe-iso` имеет доступ только на чтение к новой папке. Его пароль хранится в `/etc/pxe-platform/pxe-iso-password` с правами `0600`; это отдельные учётные данные, не пароль Synology и не прежний `pxe-install`. Сервер подставляет этот пароль в `pxe-setup.cmd`, передаваемый PXE-клиенту при загрузке. Следовательно, машина внутри изолированной сети `10.30.0.0/24` может получить пароль к read-only папке. Boot возвращает HTTP 404 для этого файла при запросе из сети управления. Анонимное подключение Samba отклонено; создание каталога через учётную запись `pxe-iso` вернуло `NT_STATUS_ACCESS_DENIED`.

`wimboot` дополнительно загружает `winpeshl.ini` и `pxe-setup.cmd` до `boot.wim`. В WinPE сценарий выполняет `wpeinit`, ожидает сеть, подключает `windows11iso`, проверяет `sources/install.wim` и запускает `sources/setup.exe /InstallFrom:Y:\sources\install.wim`. Если источник недоступен, остаётся командная строка с сообщением. Скрипт хранится в репозитории как шаблон без пароля; сервер создаёт рабочий файл при старте `pxe-windows11-iso.service`.

На сервере проверено: `boot.wim` побайтово совпадает с файлом внутри смонтированного ISO; HTTP отвечает 200 на `wimboot`, `winpeshl.ini` и `boot.wim`; все PXE-службы, Samba и монтирование активны; HTTPS-админка отвечает. Пользователь повторно опубликовал меню; активный скрипт содержит оба новых `initrd`. Новая пустая ВМ 113 в OVMF с выключенным Secure Boot загрузилась по PXE до начального экрана установки Windows 11. На сервере `smbstatus` показал её подключение с адреса `10.30.0.19` к `windows11iso` под учётной записью `pxe-iso`, то есть автоматическое подключение исходного ISO сработало. После начального экрана Setup остановился на сообщении о несовместимости компьютера с Windows 11. У ВМ есть 16 ГБ памяти, четыре виртуальных процессора, SATA-диск 70 ГБ и OVMF, но в конфигурации нет `TPM State`; ожидается проверка после добавления TPM 2.0. До экрана выбора диска пока не дошли, запись на диск не запускали.

Откат автоматического старта: на странице «Меню» вернуть прежнюю версию. При необходимости вернуть бинарные файлы `/usr/local/bin/pxe-control.pre-win11-auto-20261016` и `/usr/local/bin/pxe-boot.pre-win11-auto-20261016`, затем перезапустить соответствующие службы. Отдельную Samba-папку можно убрать восстановлением `/etc/samba/smb.conf.pre-windows11iso-20261016`; после остановки `pxe-windows11-iso.service` исходный ISO останется на Synology.
