# Ubuntu Desktop: сетевая установка в OMB

[English version](en/ubuntu-desktop-pxe.md). Текущий порядок работы с установками — в [руководстве Control](control-installation.md#ubuntu-autoinstall).

OMB поддерживает несколько Ubuntu Desktop amd64 ISO из подключённых локальных и сетевых хранилищ. Для каждого проверенного ISO Agent отдельно готовит ядро, initrd, shim и каталог вариантов установки. Одним ISO могут пользоваться несколько загрузок с разными файлами Autoinstall.

## Подготовка источника

В «Библиотека → Образы ISO» загрузите файл или найдите ISO после сканирования хранилища. У нужного образа выберите «Создать загрузку»: OMB проверит содержимое, архитектуру и контрольную сумму, затем откроет форму с выбранным ISO. Ubuntu Server, ARM64 и неполные образы не поддерживаются. Тип по имени файла в библиотеке служит подсказкой, а не результатом проверки. Если название файла не указывает на Ubuntu, доступно действие «Проверить для Ubuntu».

В форме задайте название и каталог, при необходимости выберите файл Autoinstall. После сохранения Agent подготовит источник; при ошибке загрузка останется в списке с действием повторной подготовки. Загрузку нужно отдельно добавить в черновик и опубликовать меню. Исходный ISO остаётся в хранилище; подготовленные файлы и новые URL закреплены за идентификатором источника и SHA-256 ISO. Подмена файла или несовпадение подготовленных данных блокируют публикацию.

Адрес Boot, доступный клиентам, задаётся в `/etc/omb/control.env` через `OMB_CONTROL_BOOT_BASE_URL`. BIOS загружает ядро напрямую; UEFI использует shim из того же ISO. Доступ к хранилищу должен быть у Boot, включая родительские каталоги.

Старые адреса `/images/ubuntu-desktop.iso` и `/assets/ubuntu/` сохраняются только для ранее опубликованных версий с подтверждённым источником. Выбор другого ISO не меняет их привязку. Версию, для которой источник нельзя подтвердить, восстановить нельзя. Не заменяйте содержимое старого каталога и не применяйте миграцию на работающем сервере без проверенного соответствия ISO и резервной копии.

## Установка и Autoinstall

В «Загрузках» создайте вариант Ubuntu. Без файла ответов загрузка ручная. Для автоматизации создайте или выберите неизменяемый файл в «Библиотека → Файлы ответов → Ubuntu Autoinstall». Доступны интерактивная разметка, полная очистка диска по выбору установщика с предупреждением об удалении данных и очистка только диска с точным серийным номером. Добавьте установку в черновик меню и опубликуйте.

Проверьте получение согласованной пары NoCloud `user-data` и `meta-data` и ожидаемое поведение установщика на одноразовом диске ВМ. Успешная выдача файлов не подтверждает завершение установки ОС. Условия доступа к данным и работу конструктора см. в [руководстве Control](control-installation.md#ubuntu-autoinstall).

## Проверка и восстановление

`casper` загружает ISO в память. Для ранее проверенного ISO размером около 6,5 ГБ использовалась ВМ с 16 ГБ ОЗУ; при 4 ГБ загрузка завершалась `No space left on device`. Объём памяти для другого ISO проверяйте отдельно.

До технического перехода пользователь подтвердил рабочий стол Ubuntu в SeaBIOS и OVMF с Secure Boot и без него. Полный повторный прогон текущей сборки, включая Autoinstall, отложен до завершения основной разработки.

При неудачной загрузке проверьте память клиента, доступность ISO, соответствие ядра и initrd, журналы Boot и состояние хранилища. Через «Меню → Версии» можно вернуть доступную прежнюю версию; откат обновлений описан в [руководстве по офлайн-выпускам](offline-release.md).
