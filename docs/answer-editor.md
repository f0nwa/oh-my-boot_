# Редактор файлов ответов

> Актуальные команды установки используют целевые имена OMB. Датированные отчёты о развёртывании, исходные пути резервных копий и результаты относятся к стенду до миграции; стенд переведён на OMB 31.10.2026. См. [план технической миграции](../docs/superpowers/plans/2026-10-31-omb-technical-migration.md). Результаты и оставшаяся приёмка: [отчёт миграции](research/2026-10-31-omb-technical-migration.md).

«Библиотека → Файлы ответов → Создать в редакторе» собирает `autounattend.xml` для установки Windows. У каждого готового файла в списке есть кнопка «Открыть в редакторе». Редактор — перенос на Go библиотеки [cschneegans/unattend-generator](https://github.com/cschneegans/unattend-generator) (на ней работает сайт [schneegans.de](https://schneegans.de/windows/unattend-generator/)), поэтому настройки и результат те же, что на сайте.

## Страница

- **Слева — оглавление** из 12 разделов: язык и регион, диск и установка, редакция и ключ, имя и время, учётные записи, проводник и «Пуск», оформление, сеть и ВМ, удаление приложений, оптимизации и защита, скрипты, свой XML. Отметки: «изм.» — раздел отличается от Windows по умолчанию; число — сколько приложений, скриптов или элементов своего XML; «N вопр.» — к разделу есть вопросы.
- **В центре — один раздел.** Над ним наборы-заготовки: «Как Windows по умолчанию», «Только язык и ключ — диск вручную», «Лаборатория: локальная учётка, автовход». Набор заменяет все настройки.
- **Справа — вкладки:** «Что получится» — сводка простыми словами; «XML» — файл целиком, изменившиеся строки подсвечены; «Вопросы» — например, пароли открытым текстом или отключённая защита Windows. Метка «Стирает диск» появляется, если файл сам размечает диск: пункт меню с ним получит «WIPES DISK».
- **Сохранить к образу** — образ ISO, название пункта меню латиницей и папка. Файл сохраняется как новый файл ответов этого образа; в меню он попадает, когда его выбирают в новой установке и публикуют меню. Правка существующего файла **всегда сохраняется новым файлом**: исходный и пункт меню с ним не меняются.
- **Скачать autounattend.xml** — тот же файл, для USB, ISO или проверки.
- Имя компьютера подсказывается из списка машин.
- Ошибки генератора («строка длиннее 255 символов», «нужен хотя бы один администратор» и т. п.) показываются над формой, введённое остаётся.
- Файл больше 1 МБ к образу не сохраняется, но скачивается.
- Страница работает и без JavaScript: переход между разделами, наборы и «ещё строка» отправляют форму. С JavaScript разделы переключаются на месте, а сводка и XML обновляются при каждом изменении.

Права: открывать и скачивать — все; сохранять к образу — администратор и оператор. Аудит: `windows-answer.create` с пометкой `editor=1`. Компьютеры в доверенном PXE-сегменте могут получить содержимое файла, включая пароли и ключи; «Скрывать пароли» только кодирует их в base64.

## Разметка диска при установке по сети

- **«Установщик Windows»** — диск выбирают на экране установщика; файл ответов на диск не влияет. Подходит для любой установки.
- **«Стереть диск и разметить автоматически»** — вместо установщика на этапе windowsPE работает сгенерированный `pe.cmd`: выбирает диск (по номеру, по размеру и типу или спрашивает), размечает его (GPT/MBR по прошивке, с разделом восстановления или без), разворачивает образ `dism`-ом, делает раздел загрузочным и перезагружается. `pe.cmd` ищет образ как `<диск>:\sources\install.wim`, поэтому при установке по сети скрипт WinPE для каждого файла ответов подключает папку профиля ещё раз буквой `I:` и копирует файл ответов в `X:\autounattend.xml`. Файлы, сохранённые к образу до 24.10.2026, этого подключения не имеют — для режима `pe.cmd` их нужно сохранить заново.
- **«Свой сценарий pe.cmd»** — то же, но скрипт целиком свой.

## Как открываются файлы

- **Файл, сохранённый редактором,** хранит свои настройки внутри XML: элемент `<Editor xmlns="urn:omb:unattend-editor" version="1">` с JSON в CDATA (при скрытых паролях — в base64). Windows Setup элементы чужого пространства имён пропускает. Такой файл открывается точно. Если его потом правили руками, редактор предупредит: при сохранении ручные правки пропадут.
- **Чужой файл** (с сайта Schneegans, написанный вручную, от другого генератора) разбирается. Знакомые настройки идут в форму: язык и раскладки, часовой пояс, имя компьютера, редакция и ключ, ключ активации, обход проверок Windows 11, учётные записи и автовход, экраны OOBE, папка `$OEM$`, скрипты файлов Schneegans. Всё остальное сохраняется дословно в разделе «Свой XML» и при сборке вливается обратно в тот же компонент: пункт списка (`RunSynchronous`, `DriverPaths`, учётки и т. п.) добавляется, если такого нет, прочий элемент заменяет одноимённый из формы.
- **Самопроверка:** настройка переходит в форму, только если пересборка воспроизводит её значение точно; иначе она остаётся дословным XML. Поэтому при открытии ничего не теряется. Не сохраняются только комментарии XML — редактор показывает, сколько их было.
- **Скрипты файлов Schneegans** (`Specialize.ps1`, `FirstLogon.ps1`, `UserOnce.ps1`, `DefaultUser.ps1`) запускаются на тех же этапах из `C:\Windows\Setup\Scripts\Imported\`; их вспомогательные файлы остаются как были.
- Файлы в UTF-16 с BOM читаются.

Плашка над формой показывает, что перенесено в форму и что осталось как свой XML.

## Ограничения

- Проверка итогового XML по схеме XSD оригинала не перенесена: проверяется только, что XML правильно построен.
- Ошибки разбора своего XML (профиль Wi-Fi, панель задач, плитки «Пуска», AppLocker) — от Go, а не от .NET: начало сообщения то же, причина своими словами.
- JSON закреплений «Пуска» принимается как в оригинале (оборванный текст допустим), но без комментариев и одинарных кавычек.
- Компоненты из «Свои компоненты» добавляются в порядке строк; на сайте порядок нескольких своих компонентов одного прохода случаен.

Подробно об отличиях — [internal/unattend/UPSTREAM.md](../internal/unattend/UPSTREAM.md).

## Как обновить порт из upstream

Порт сверяется с оригиналом по эталонам: `internal/unattend/testdata/golden/*.json` — наборы настроек, `*.xml` или `*.err` — что из них сделала исходная C#-библиотека. `go test ./internal/unattend/` сравнивает вывод порта с эталонами байт в байт. Сборке проекта .NET не нужен; он нужен только для пересборки эталонов (`apt-get install dotnet-sdk-8.0`).

1. Запустить `scripts/unattend-update.sh <коммит>`. Скрипт:
   - забирает upstream на этом коммите в `tools/unattend-golden/upstream/`;
   - копирует `resource/` в `internal/unattend/resource/`;
   - записывает новый коммит в `generator.go` (`UpstreamCommit`), `UPSTREAM.md` и `tools/unattend-golden/fetch.sh`;
   - пересобирает эталоны новым оригиналом (`scripts/unattend-golden.sh`);
   - показывает, какие файлы C# изменились, и запускает тесты.
2. Если тесты падают — перенести изменения из `git -C tools/unattend-golden/upstream diff <старый> <новый> -- modifier/ Main.cs`: модификатор `X.cs` переносится в `internal/unattend/modifiers_*.go` (имена функций — как классы C#), модель настроек — в `config.go`. Тест печатает первую отличающуюся строку.
3. Новые настройки upstream добавить в форму (`templates/answer_editor.html`, переводы — `internal/control/i18n_editor.go`) и, если они встречаются в чужих файлах, в разбор (`importer.go`).
4. Для новых настроек добавить эталоны: JSON в `testdata/golden/`, затем `scripts/unattend-golden.sh testdata/golden/<имя>.json`.
5. Обновить дату в `UPSTREAM.md`, прогнать `go test ./...`, закоммитить.

Проверка вхолостую — запустить скрипт на текущем коммите: эталоны и ресурсы не меняются, тесты проходят. 24.10.2026 новых коммитов после `27237f8` в upstream не было.
