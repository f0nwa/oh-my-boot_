# Images: каталог ISO и хранилища OMB

[English version](en/images-installation.md). Порядок работы с загрузками и меню — в [руководстве Control](control-installation.md#загрузки-и-меню).

Images хранит каталог ISO в базе `omb_images` и обслуживает локальный API `/run/omb-images/images.sock`. Найденный ISO ещё не является пунктом меню: создайте загрузку из образа и опубликуйте меню. Подготовка выполняется автоматически при сохранении загрузки.

## Первая установка

Сначала подготовьте Boot, Agent и PostgreSQL по [руководству сервера](installation.md). Следующие команды предназначены для нового сервера. На существующем стенде сохраняйте базу, настройки и зарегистрированные хранилища.

Сборка в корне репозитория:

~~~sh
mkdir -p dist
CGO_ENABLED=0 GOOS=linux GOARCH=amd64 go build -trimpath -o dist/omb-images ./cmd/omb-images
CGO_ENABLED=0 GOOS=linux GOARCH=amd64 go build -trimpath -o dist/omb-imagesctl ./cmd/omb-imagesctl
~~~

Перенесите `dist` и `deploy` на сервер. Серверные команды выполняются из каталога с этими файлами в Bash под root:

~~~sh
install -m 0755 dist/omb-images dist/omb-imagesctl /usr/local/bin/
useradd --system --user-group --home-dir /var/lib/omb-images --shell /usr/sbin/nologin omb-images
install -d -m 0750 -o root -g root /etc/omb
install -d -m 0750 -o omb-images -g omb-images /var/lib/omb-images
install -d -m 2770 -o root -g omb-images /var/lib/omb-images/iso
install -d -m 0755 -o root -g root /mnt/omb-smb-upload
runuser -u postgres -- psql -v ON_ERROR_STOP=1 -c 'CREATE ROLE "omb-images" LOGIN'
runuser -u postgres -- createdb --owner=omb-images omb_images
runuser -u omb-images -- psql -v ON_ERROR_STOP=1 --dbname=omb_images < deploy/sql/images.sql
~~~

Создание настроек защищено от перезаписи:

~~~sh
(
  set -eu
  test ! -e /etc/omb/images.env
  cat > /etc/omb/images.env <<'ENV'
OMB_IMAGES_DATABASE_URL="host=/var/run/postgresql dbname=omb_images user=omb-images"
ENV
  chmod 0640 /etc/omb/images.env
)
install -m 0644 deploy/systemd/omb-images.service /etc/systemd/system/
systemctl daemon-reload
systemctl enable --now omb-images.service
~~~

Установите Control по [его руководству](control-installation.md). Его юнит содержит `SupplementaryGroups=omb-images`, чтобы обращаться к сокету Images. При изменении групп юнита уже работающую службу нужно перезапустить.

## Регистрация и сканирование

Созданный локальный каталог регистрируется один раз:

~~~sh
runuser -u omb-images -- env OMB_IMAGES_DATABASE_URL='host=/var/run/postgresql dbname=omb_images user=omb-images' \
  /usr/local/bin/omb-imagesctl add-path -name Local -kind local -root /var/lib/omb-images/iso
~~~

`-kind mounted` предназначен для уже смонтированной файловой системы: нужен абсолютный путь к настоящей точке монтирования без символьных ссылок.

Сетевые хранилища SMB и NFS подключаются администратором через «Система → Хранилища» (кнопка «Подключить хранилище ▾»):
- **SMB:** прямой путь вида `//nas.example.com/share/iso` и учётные данные (пользователь, пароль, домен). Для SMB нужен пакет `cifs-utils`; Agent сохраняет учётные данные в `/etc/omb/smb/<ключ>` с правами `0600`.
- **NFS:** адрес сервера (например, `nas.example.com` или IPv4/IPv6) и абсолютный путь экспорта (например, `/volume1/iso` или `/export/iso`). Поддерживаются версии **NFSv4.1** (по умолчанию, TCP-порт 2049) и **NFSv3** (RPC portmapper 111, nfs 2049, опция `nolock`). Для NFS требуется системный пакет `nfs-common` (`mount.nfs`). Agent сохраняет параметры подключения в `/etc/omb/nfs/<ключ>.json` с правами `0600`.

**Режимы доступа и автоопределение прав NFS:**
NFS определяет права по Unix UID/GID процесса, а не по параметрам монтирования. При подключении и последующих проверках доступности («Обновить» в меню `☰`) Agent монтирует экспорт для чтения в `/mnt/omb-nfs/<ключ>` и автоматически выполняет пробу записи во временной точке `/mnt/omb-nfs-upload/<ключ>` от имени системного пользователя `omb-images`:
- Если экспорт на NAS разрешает запись и создание файлов пользователю `omb-images`, хранилище переходит в режим **чтение и запись** (доступны загрузка и удаление ISO).
- Если экспорт доступен только для чтения либо у `omb-images` нет прав на создание/удаление файлов на NAS, хранилище остаётся в режиме **только чтение** (сканирование каталога, просмотр свободного места и подготовка загрузок работают штатно, а загрузка и удаление ISO блокируются).
- При изменении прав на NAS нажмите «Обновить» в меню `☰` хранилища, чтобы переопределить режим доступа без переподключения.

**Требования и рекомендации по настройке экспорта NFS на NAS:**

Поскольку служба каталога `omb-images` работает от локального системного UID/GID сервера OMB (которого обычно нет на внешнем NAS), на NAS с ACL (например, Synology DSM) вариант `Без сопоставления` (No mapping) приводит к ошибке `permission denied` при сканировании. Настраивайте Squash в зависимости от выбранного режима работы:

1. **Тестовый и базовый рабочий режим «только чтение» (загрузка ISO через NAS вручную, OMB только читает и раздаёт по PXE):**
   - **Права экспорта на NAS:** `Только для чтения` (`ro`).
   - **Squash / сопоставление пользователей:**
     - На Synology DSM: `Сопоставить всех пользователей с admin` (если доступ к папке ограничен по ACL; сам экспорт при этом остаётся `Только для чтения`, поэтому клиент ничего не сможет изменить) либо `Сопоставить всех пользователей с guest` (если у `guest` включены права чтения этой папки).
     - На Linux NFS-сервере: опции `ro,all_squash` с `anonuid`/`anongid` пользователя, имеющего права на чтение каталога (`o+rx` на папки, `0644` на файлы `.iso`).
   - **Рекомендовано на Synology DSM:** включить асинхронный режим и разрешить подключения с непривилегированных портов (выше 1024).

2. **Рабочий режим «чтение и запись» (полное управление: загрузка и удаление ISO через веб-интерфейс OMB):**
   - Для рабочего контура рекомендуется выделить **отдельную общую папку / экспорт** только под образы OMB (без сторонних пользовательских данных).
   - **Права экспорта на NAS:** `Чтение/запись` (`rw`).
   - **Squash / сопоставление пользователей:**
     - На Synology DSM: `Сопоставить всех пользователей с admin` (либо с выделенной сервисной учётной записью NAS с правами записи только в эту папку).
     - На Linux NFS-сервере: `rw,all_squash` с `anonuid`/`anongid` владельца каталога либо выдача прав записи на каталог локальным UID/GID `omb-images` (узнать командой `id omb-images`).
   - **Безопасность и права файлов:** при `root_squash` (по умолчанию на большинстве NAS) loop-монтирование ISO службами `omb-agent` и `omb-winiso-prepare` читает файлы как `nobody`, поэтому каталоги должны иметь права `o+rx`, а файлы `.iso` — `0644` (при загрузке через веб-панель OMB выставляет `0644` автоматически). При `no_root_squash` root сервера OMB сохраняет прямой доступ.
   - После изменения прав на NAS нажмите **«Обновить»** в меню `☰` хранилища, чтобы OMB повторно выполнил пробу записи и переключил статус.

Оператор и администратор могут запускать сканирование, наблюдатель видит каталог. Проверка доступности работает в фоне; при ошибке прежние записи сохраняются. Прерванное перезапуском сканирование отмечается ошибкой, после чего его можно повторить. Восстановление управляемых монтирований и удаление хранилищ описаны в [руководстве Control](control-installation.md#доступность-хранилищ-и-восстановление).

## Загрузка ISO

В библиотеке выберите доступное для записи хранилище и ISO до 32 ГиБ. Поле папки появляется, только если в хранилище есть подпапки; иначе файл сохраняется в корне. Полный ISO передаётся на выбранное хранилище; после передачи проверяются размер и SHA-256. Существующий файл не перезаписывается, отмена удаляет временный файл. Публикация меню выполняется отдельно.

Для SMB и NFS используются раздельные точки монтирования: `/mnt/omb-smb/<ключ>` или `/mnt/omb-nfs/<ключ>` для чтения и `/mnt/omb-smb-upload/<ключ>` или `/mnt/omb-nfs-upload/<ключ>` для записи. Учётная запись или права на NAS должны разрешать запись. Локальная загрузка использует `/var/lib/omb-images/iso`; группа `omb-images` должна иметь право записи, а юнит — разрешать этот путь. Для удаления ISO из локального, примонтированного или сетевого (SMB/NFS) хранилища пользователь `omb-images` также должен иметь право записи в соответствующий каталог. Свободное место показывается для файловой системы выбранного хранилища.

## Образы Windows, XML и драйверы

В разделе «Загрузки» создайте загрузку из Windows x64 ISO. Подготовка начнётся автоматически после сохранения. Agent проверяет источник, монтирует ISO только для чтения и готовит загрузочные файлы в `/srv/omb/tftp/windows-profiles/<ID>/`. Полный ISO остаётся на хранилище; клиент получает установочные файлы через отдельную шару `ombisos` и учётную запись `omb-iso`. Учётные данные внешнего NAS в WinPE не передаются.

Архитектура доставки Windows Setup при использовании сетевого хранилища:
`NAS (экспорт NFS или шара SMB) → сервер OMB (/mnt/omb-nfs/<ключ> или /mnt/omb-smb/<ключ>) → loop-монтирование ISO (/mnt/omb-iso/profiles/<ID>) → локальная Samba-шара ombisos → клиент WinPE`. Клиенты PXE и WinPE не подключаются к NAS напрямую и не требуют сетевых протоколов NAS; на клиенте работает стандартный клиент SMB к серверу OMB.

Для подготовки нужны установленный `omb-winiso-prepare`, [юнит профиля](../deploy/systemd/omb-winiso@.service), [шаблоны](../deploy/boot-assets/windows-profiles/) в `/usr/share/omb/windows-profiles`, конфигурация [Samba](../deploy/samba/smb.conf) и пароль `/etc/omb/omb-iso-password`. Каталоги монтирования и конфигурации: `/mnt/omb-iso/profiles`, `/etc/omb/winiso`. Эти компоненты устанавливаются в составе [серверного комплекта](offline-installation.md); одна установка Images их не заменяет. Локальные исходные ISO для Windows должны находиться внутри `/var/lib/omb-images` либо на управляемом хранилище SMB или NFS.

Загрузите проверенный Windows XML в «Библиотека → Файлы ответов», а INF с сопутствующими файлами — в «Библиотека → Драйверы». При создании или редактировании загрузки выберите нужные ISO, XML и INF, дождитесь подготовки и опубликуйте меню. Исходный ISO остаётся прежним. Подробности — в [руководстве Control](control-installation.md#каталог-драйверов-winpe).

XML может содержать пароли и ключи. Скрипты образов, конфигураций драйверов и файлы ответов выдаются только доверенной PXE-подсети `10.30.0.0/24`; из сети управления возвращается 404.

Каталог показывает все найденные ISO, но наличие файла не означает поддержку его загрузки. Тип в таблице определяется по имени, а содержимое проверяется при подготовке. Для Ubuntu Desktop amd64 проверенный ISO выбирается отдельно; несколько образов могут использоваться одновременно. Поддерживается Strelec x64 со структурой `SSTR`: OMB выбирает WinPE 11, а при его отсутствии — WinPE 10, включает штатный PXE-сценарий из WIM и подключает пакет программ того же ISO через шару `ombisos`. WIM копируется без изменения содержимого. Загрузчики BIOS/UEFI и `boot.sdi` берутся из того же ISO и передаются отдельно; его BCD адаптируется для выбранного WIM и виртуальных путей wimboot. Драйверы WinPE выбираются в форме загрузки теми же пакетами и отдельными INF; OMB готовит отдельную копию WIM и загружает драйверы до подключения SSTR. XML установщика Windows для такой загрузки недоступен. Прочие сервисные WinPE без известного сценария и ARM64 пока не поддерживаются.

## Диагностика

Выполняется под root; явная группа нужна для проверки сокета от имени Control вне systemd:

~~~sh
systemctl is-active omb-images omb-control omb-boot omb-agent omb-dnsmasq
runuser -u omb-images -- psql -XAt --dbname=omb_images -c 'SELECT 1'
runuser -u omb-control -g omb-images -- curl --fail --unix-socket /run/omb-images/images.sock http://unix/catalog
journalctl -u omb-images -u omb-agent -n 100 --no-pager
~~~

Перед обновлением сохраните согласованную копию баз, конфигурации и файлов. [Восстановление](recovery.md), [состояние стенда и оставшиеся проверки](research/2026-10-31-omb-technical-migration.md), [доступ к прежним отчётам](project-history.md).
