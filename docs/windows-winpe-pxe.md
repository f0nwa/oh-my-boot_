# Windows 10: первая проверка WinPE по PXE

Эта порция добавляет в загрузочное меню Windows 10 x64 и загружает `sources/boot.wim` через подписанный `wimboot`. Цель проверки — дойти до среды WinPE или окна установщика. Доступ к полным файлам установки по SMB и установка на диск в эту порцию не входят.

## Источники и файлы

- ISO: `19045.6280.250817-2324.22H2_RELEASE_SVC_PROD3_CLIENTPRO_OEMRET_X64FRE_RU-RU.ISO` в подключённой SMB-папке `//192.168.10.10/Downloads/iso`.
- `wimboot` 2.9.0: `https://github.com/ipxe/wimboot/releases/download/v2.9.0/wimboot`; SHA-256 `5f067ccdc4d084d5bf77b6c853bd0f8402dfc2b4cd1b103d358993ae97fae8e3`.
- `sources/boot.wim` этого ISO: 597 191 021 байт; SHA-256 `8401543d872d0feb851efa2faf87a6d45e472db6b1e3c65d144af2cbd8df0de4`.

Сервер хранит эти два файла в `/srv/pxe/tftp/windows/wimboot` и `/srv/pxe/tftp/windows10/boot.wim`. Он не публикует SMB-шару целиком. Сверка `cmp` подтвердила, что копия WIM равна файлу внутри ISO. `sbverify --list` на Ubuntu показал подписи wimboot от цепочек Microsoft Corporation UEFI CA 2011 и Microsoft UEFI CA 2023. Наличие подписи не заменяет отдельный запуск клиента с Secure Boot.

## Публикация и проверка

В админке **Меню** отметить **Windows 10 x64 — запуск WinPE** и оставить включённым Ubuntu, если он нужен. Нажать **Опубликовать**. Прежняя версия меню остаётся доступной для отката.

На тестовой PXE-ВМ 112 с 16 ГБ ОЗУ сначала загрузить Windows 10 в OVMF с Secure Boot выключенным. Проверить, что среда WinPE/окно установщика открылась; если установщик попросит файлы с носителя, записать это как ожидаемую границу текущего этапа. Не выбирать диск и не запускать установку. После успешного запуска повторить с Secure Boot включённым, а затем с SeaBIOS.

Пользователь подтвердил: в OVMF окно установки Windows 10 появилось и с выключенным, и с включённым Secure Boot. `ipconfig` внутри WinPE не показал сетевого адаптера при модели VirtIO у тестовой ВМ. Проверяется гипотеза об отсутствующем драйвере VirtIO заменой модели только у ВМ 112 на Intel E1000 с сохранением `vmbr0` и VLAN 30. Проверка SeaBIOS ещё не выполнена. Запуск WinPE не подтверждает доступ к полным установочным файлам или успешную установку ОС.

Проверка серверных файлов: `HEAD` вернул HTTP 200 и размеры 76 064 байта для `wimboot` и 597 191 021 байт для `boot.wim`. Запрос диапазона первых 1024 байт WIM вернул HTTP 206 и ровно 1024 байта. После замены Control все пять служб остались активны, HTTPS-страница входа ответила HTTP 200, SHA-256 действующего меню до и после замены остался `2777c5df23b82398483177bb8dc73999dd1bdc052f2601642682698bbb6d30f6`. До ручной публикации пункт Windows 10 в действующем меню отсутствует.

## Откат

Если профиль не загрузится, вернуть прежнюю версию через **Меню → Версии**. Прежний бинарный файл Control лежит в `/var/backups/pxe-platform-pre-winpe-20261016/pxe-control`. Восстановить его в `/usr/local/bin/pxe-control` и перезапустить только `pxe-control`; Boot, proxy-DHCP и текущий опубликованный снимок меню работают независимо от панели. Файлы Windows 10 в `/srv/pxe/tftp` можно удалить после исключения пункта из меню.

## Следующий шаг

После проверки WinPE добавить доступ к распакованным файлам установщика по SMB и повторить для Windows 11 x64. Для Windows 11 использовать тот же закреплённый выпуск wimboot, который поддерживает извлечение `boot.stl` из новых WIM.

Основа способа загрузки: [iPXE wimboot](https://ipxe.org/wimboot), [iPXE Windows PE](https://ipxe.org/howto/winpe), [выпуск wimboot 2.9.0](https://github.com/ipxe/wimboot/releases/tag/v2.9.0).
