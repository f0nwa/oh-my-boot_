# Windows 11 x64: первая проверка WinPE

На сервере найден ISO `26100.5067.250818-2008.GE_RELEASE_SVC_PROD3_CLIENTPRO_OEMRET_X64FRE_RU-RU.ISO` в подключённой SMB-папке. Для начальной загрузки из него скопирован `sources/boot.wim` в `/srv/pxe/tftp/windows11/boot.wim`. Размер — 698 729 786 байт, SHA-256 — `33f30dccd7479ddb31fc6cd692ca7f420eaee5af388f8ecc8fa3f9524a31d4a4`; `cmp` подтвердил совпадение с файлом в ISO. Boot отдаёт его по `/assets/windows11/boot.wim`: HTTP HEAD 200, запрос первых 1024 байт — 206. Для загрузки используется уже закреплённый и проверенный `wimboot` 2.9.0 из [профиля Windows 10](windows-winpe-pxe.md).

Админка предлагает отдельный пункт **Windows 11 x64 — запуск WinPE**. Его публикация выполняется вручную через страницу **Меню**, сохраняя выбранные Ubuntu и Windows 10. Замена бинарного файла Control не меняет действующее опубликованное меню; его SHA-256 до и после замены остался `c3730b5ceed31bc218b7ab9cd42c1f3fc6e4d944e739117a85b2ff6a8d2f676c`. Предыдущий бинарный файл сохранён в `/var/backups/pxe-platform-pre-win11-20261016/pxe-control`.

Пользователь опубликовал пункт Windows 11; активное меню содержит Ubuntu, Windows 10 и Windows 11 (SHA-256 `7120f842b72b1f2dda998c79f1c9385c21c1461f7eacb7f82d96d5ec51729b89`). На ВМ 112 в OVMF окно установки Windows 11 появилось как с выключенным, так и с включённым Secure Boot. Установку на диск не запускали.

## Полные файлы установки

Содержимое ISO скопировано из подключения только для чтения в `/srv/pxe/installers/windows11` (1054 файла). Сверка `cmp` подтвердила совпадение `sources/boot.wim` и `sources/install.wim` с ISO; размер `install.wim` — 8 693 893 898 байт. Отдельная папка `\\10.30.0.10\windows11` задана в [`deploy/samba/smb.conf`](../deploy/samba/smb.conf) с теми же ограничениями, что и Windows 10: только `10.30.0.0/24`, вход `pxe-install`, обязательная подпись SMB и чтение без записи. Пароль тот же, что для Windows 10; пароль исходного хранилища клиенту не передаётся.

На сервере `testparm` принял новую конфигурацию. `smbclient` от имени `pxe-install` прочитал `setup.exe` побайтово, увидел `install.wim`, но не смог создать каталог; анонимный вход отклонён. Шара Windows 10 после изменения осталась доступна. В WinPE с включённым Secure Boot пользователь выполнил `wpeutil InitializeNetwork`, подключил `\\10.30.0.10\windows11` и подтвердил, что `Z:\sources\install.wim` виден.

Сразу после запуска `Z:\setup.exe` установщик запросил драйвер для обнаружения оборудования. В этом Windows 11 WinPE команда `diskpart` → `rescan` → `list disk` **не показала** 32-ГБ диск ВМ 112, подключённый как `scsi0` через VirtIO SCSI single. Пользователь выключил ВМ, отсоединил диск без удаления его образа и подключил тот же образ как `sata0`. После новой загрузки WinPE и `rescan` команда `list disk` показала диск 32 ГБ. Это подтверждает проблему обнаружения диска через VirtIO SCSI в текущем Windows 11 WinPE. [Proxmox описывает такой способ смены шины](https://pve.proxmox.com/wiki/Migrate_to_Proxmox_VE). Однако `Z:\setup.exe` и с SATA снова показал запрос драйвера: обнаружение диска и причина остановки установщика — отдельные вопросы. На сервере проверено наличие исполняемого `sources/setup.exe`, рекомендованного [Microsoft для запуска из WinPE](https://learn.microsoft.com/en-us/windows-hardware/manufacture/desktop/windows-setup-supported-platforms-and-cross-platform-deployments?view=windows-11); его запуск из уже открытого WinPE сразу возвращает командную строку и не меняет активное окно установщика. В этой среде `setuperr.log` лежит в `X:\$WINDOWS.~BT\Sources\Panther`, а не в `X:\Windows\Panther`; его содержимое ещё не получено. Диск не очищали и установку не начинали.

Для отката отключить `smbd.service`, восстановить `/var/backups/pxe-platform-pre-win11-smb-20261016/smb.conf` в `/etc/samba/smb.conf` и запустить `smbd.service`. Старую папку Windows 10 откат не затрагивает. Полную копию `/srv/pxe/installers/windows11` удалять только после завершения клиентских проверок.
