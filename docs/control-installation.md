# Control и HTTPS-админка на тестовой ВМ

Адрес: **https://192.168.10.135:8443**. Сертификат самоподписанный, с IP в SAN; браузер попросит подтвердить доверие. Лабораторный сертификат действует 90 дней.

## Службы

`pxe-control` — отдельный Go-процесс и отдельная база PostgreSQL `pxe_control`. Браузер обращается только к нему. Control вызывает Boot и Agent через локальные Unix-сокеты. `pxe-boot` продолжает отдавать последнее опубликованное меню на `10.30.0.10:8080`, а `pxe-agent` — поддерживать proxy-DHCP на `ens19`, когда Control остановлен. Список интерфейсов, доступных для изменения из панели, в лаборатории содержит только `ens19`.

## Каталоги загрузочного меню

На странице «Меню» в блоке «Каталоги в PXE-меню» можно указать путь для каждого уже подготовленного профиля. Например, `Windows/Установщики` создаёт два вложенных уровня. Пустое поле оставляет пункт в главном меню. Каталоги образуются из выбранных пунктов и не зависят от расположения ISO на SMB-шаре. После нажатия «Опубликовать» новая структура применяется целиком; прежнюю версию можно вернуть из списка версий. Обнаруженные, но ещё не подготовленные ISO в меню не добавляются.

Новые профили Windows ISO создаются на странице «Образы». После подготовки каждый из них можно отдельно отметить на странице «Меню» и поместить в каталог. Версия меню хранит выбранные ID, поэтому возврат к старой версии восстанавливает тот же набор пунктов. Перед публикацией и возвратом Control проверяет доступность исходного ISO и подготовленных файлов. Старые статические пункты Windows 10/11 сохраняются на время перехода.

16.10.2026 на тестовой ВМ установлен новый бинарный файл Control; HTTPS отвечает, служба активна. Пользователь опубликовал каталоги `Linux` и `Windows` и подтвердил переход в `Windows` и возврат. Изначальная подпись `Назад` не отображалась на PXE-экране: пункт был пустой строкой. Генератор изменён: `.. Back` расположен первым пунктом каждого каталога. После повторной публикации пользователь подтвердил, что этот пункт виден и возвращает в главное меню. Предыдущие бинарные файлы сохранены в `/usr/local/bin/pxe-control.pre-menu-folders`, `/usr/local/bin/pxe-control.pre-back-first` и `/usr/local/bin/pxe-control.pre-ascii-back`.

## Установка

Собрать Linux x86_64 версии `./cmd/pxe-boot`, `./cmd/pxe-agent`, `./cmd/pxe-control`, `./cmd/pxe-controlctl` с `CGO_ENABLED=0 GOOS=linux GOARCH=amd64 go build`. Установить двоичные файлы в `/usr/local/bin`, а [юниты](../deploy/systemd) — в `/etc/systemd/system`. До замены Boot и Agent сохранить их текущие бинарные файлы и юниты для отката.

Создать системные группу и пользователя `pxe-control`, одноимённую PostgreSQL-роль и базу `pxe_control`. Применить [схему Control](../deploy/sql/control.sql) от имени `pxe-control`. База `pxe_boot` остаётся отдельной.

Настройки `/etc/pxe-platform/control.env`:

```ini
PXE_CONTROL_LISTEN=192.168.10.135:8443
PXE_CONTROL_INTERFACES=ens19
PXE_CONTROL_DATABASE_URL=host=/var/run/postgresql dbname=pxe_control user=pxe-control
```

Сертификат `control.crt` и ключ `control.key` находятся в `/var/lib/pxe-platform-control`; каталог принадлежит `pxe-control` и имеет права `0700`, ключ — `0600`. Для лаборатории сертификат создан с `subjectAltName=IP:192.168.10.135`. После установки выполнить `systemctl daemon-reload`, перезапустить Boot и Agent, затем включить Control. **При установке панели DHCP-режим и настройки Keenetic не меняются.**

Первый администратор создан локальной командой `pxe-controlctl create-admin -username fonwa` с паролем из stdin. Пароля по умолчанию нет. При потере доступа команда `pxe-controlctl reset-password -username fonwa` принимает новый пароль из stdin и завершает прежние сеансы. Для обеих команд нужна переменная `PXE_CONTROL_DATABASE_URL` от имени системного пользователя `pxe-control`.

## Каталог драйверов WinPE

На странице «Драйверы» можно загрузить папку с файлами драйвера или ZIP. Пакет должен содержать INF и все файлы, на которые он ссылается. После импорта администратор создаёт конфигурацию: подготовленный Windows ISO, при необходимости существующий XML-сценарий, название пункта меню и нужные INF. Кнопка «Подготовить» создаёт отдельный `boot.wim` и сценарий запуска. Конфигурация появляется в форме страницы «Меню», но попадает в PXE только после её выбора и нажатия «Опубликовать». Один ISO допускает несколько таких пунктов; ручной пункт сохраняется отдельно.

Номер записи и выбранные INF видны в админке «Меню», чтобы различать одноимённые пункты. Администратор может удалить неиспользуемую конфигурацию на странице «Драйверы», XML-сценарий или Windows-профиль на странице «Образы». Сначала нужно снять запись с публикации меню; профиль также нельзя удалить, пока от него зависят сценарии или конфигурации. Вместе с записью удаляются её подготовленные файлы. Общий WIM сохраняется до удаления последней использующей его конфигурации; импортированные драйверы и исходный ISO на SMB остаются. Старые версии меню с удалёнными пунктами доступны для просмотра, но недоступны для возврата.

Первый выпуск допускает загрузку до 256 МиБ, до 512 МиБ файлов после распаковки, до 4096 файлов и до 128 выбранных INF. Для пути INF, который WinPE выполняет в пакетном файле, нужны латинские буквы и другие символы ASCII. Драйверы загружаются только в WinPE; они не добавляются в установленную Windows. Файлы пакетов и подготовленные WIM сохраняются для прежних версий меню; автоматическая очистка пока не включена.

Для развёртывания установить пакет `wimtools`, применить [миграцию](../deploy/sql/2026-10-19-winpe-drivers.sql) к базе `pxe_control` от имени `pxe-control`, создать `/srv/pxe/tftp/windows-driver-wims` и `/srv/pxe/tftp/windows-driver-configs`, затем обновить Agent и Control вместе с их systemd-юнитами. Исходные WIM под `/srv/pxe/tftp/windows-profiles` не изменяются. Перед публикацией Control заново сверяет ISO, XML, пакет драйвера, производный WIM и сценарий запуска.

Миграция создала обе таблицы. Agent, Control, Boot и dnsmasq активны; HTTPS перенаправляет гостя на страницу входа. Меню сразу после развёртывания сохранило SHA-256 `43459a54e0d3dc7a8361d731062653a94293ffcadc90fce0fe3ff35f52ddabf9`; позже пользователь опубликовал тестовую конфигурацию. Импорт NetKVM и реальная загрузка WinPE с VirtIO-сетью на ВМ 113 успешно проверены при OVMF Secure Boot Enabled; подробности в [отчёте испытания](winpe-driver-test-2026-10-19.md).

Удаление Windows-профилей, XML-сценариев и конфигураций драйверов требует одного запущенного экземпляра Control: блокировки публикации, подготовки и удаления находятся в памяти процесса. При обновлении службы старый процесс нужно полностью остановить до запуска нового. Перед очисткой Control сверяет сохранённую активную версию с меню, которое реально отдаёт Boot. Исходный ISO и импортированные пакеты драйверов при удалении остаются на месте.

## Диагностика и откат

```sh
sudo systemctl status pxe-boot pxe-agent pxe-dnsmasq pxe-control
sudo journalctl -u pxe-control -u pxe-boot -u pxe-agent -n 100 --no-pager
curl --cacert /var/lib/pxe-platform-control/control.crt https://192.168.10.135:8443/login
curl -fsS http://10.30.0.10:8080/boot/menu.ipxe
```

Если панель неисправна, остановить только `pxe-control`: Boot и proxy-DHCP продолжат работу. Для полного отката на тестовой ВМ прежние бинарные файлы и юниты Boot/Agent лежат в `/var/backups/pxe-platform-pre-control/`. Вернуть их, выполнить `systemctl daemon-reload` и перезапустить Boot и Agent. Файл `/etc/pxe-platform/dnsmasq.conf` при этом не редактировать.
