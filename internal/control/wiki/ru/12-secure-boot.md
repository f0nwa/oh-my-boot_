OMB загружает UEFI-машины по сети **без отключения Secure Boot**. Для этого используется официальный загрузчик `iPXE shim 16.1`, подписанный сразу двумя сертификатами Microsoft для сторонних загрузчиков.

## Цепочка доверия и закреплённые версии

На сервере в `/srv/omb/tftp/` закреплены следующие версии загрузчиков (контрольные суммы проверяются при сборке офлайн-комплекта и скриптом `scripts/fetch-ipxe.sh`):

| Компонент | Версия | Назначение |
| --- | --- | --- |
| `iPXE` | `v2.0.0` | `undionly.kpxe` (BIOS), `ipxe.efi` и `snponly.efi` (UEFI x64, подписаны ключом iPXE) |
| `iPXE shim` | `16.1` | Первый EFI-файл (`ipxe-shim.efi` / `snponly-shim.efi`), двойная подпись **Microsoft Corporation UEFI CA 2011** и **Microsoft UEFI CA 2023** |
| `wimboot` | `v2.9.0` | Загрузка Windows WinPE и Strelec по HTTP |

При старте по сети прошивка UEFI проверяет `shim` по встроенной базе доверенных ключей `db`. Если в `db` разрешён сторонний сертификат **Microsoft UEFI CA 2011** или **Microsoft UEFI CA 2023**, прошивка запускает `shim`, а `shim` проверяет и запускает `ipxe.efi` или `snponly.efi`.

> [!NOTE]
> После перехода на `iPXE shim 16.1` с двойной подписью 2011 + 2023 прежний тестовый маршрут GRUB потерял смысл и был полностью удалён из OMB 23.11.2026.

## Почему возникает ошибка «Прошивка отклонила загрузчик»

На части корпоративных ноутбуков (Secured-core PC и новые модели Lenovo, Dell, HP) с завода в `db` включены только сертификаты для Windows (`Windows Production PCA 2011` / `Windows UEFI CA 2023`), а опция сторонних загрузчиков Microsoft UEFI CA выключена в BIOS.

В этом случае клиент скачивает `ipxe-shim.efi` по TFTP, прошивка молча отвергает его, и запроса `ipxe.efi` не происходит. Если за 30 с после TFTP-выдачи `shim` клиент не загрузил iPXE, на странице [Сейчас](/) появляется явная подсказка **«Прошивка отклонила загрузчик»**.

## Способ 1. Включение ключа в домене (SCCM / PowerShell)

Для парка машин под Windows в репозитории поставляется скрипт `scripts/windows/Enable-MicrosoftUefiCA.ps1`:

- поддерживает корпоративные ноутбуки **Lenovo** (ThinkPad/ThinkCentre), **Dell** (с 2018 года) и **HP** через штатные WMI-интерфейсы BIOS;
- проверяет наличие в `db` сертификата Microsoft UEFI CA 2011 **или** 2023;
- перед изменением настроек BIOS приостанавливает **BitLocker** на одну перезагрузку;
- умеет читать пароли BIOS из CSV-файла по `SerialNumber`;
- поддерживает режимы `-CheckOnly` (только проверка) и `-Report` (сбор отчёта по парку);
- пишет подробный журнал в `C:\Windows\Temp\OMB-MicrosoftUefiCA.log`.

Основные коды возврата: `0` (ключ уже включён), `3010` (включено, требуется перезагрузка), `2` (неподдерживаемая модель/WMI), `3` (нужен или неверный пароль BIOS), `4` (BitLocker не удалось приостановить), `1` (общая ошибка).

## Способ 2. USB-носитель UEFI CA для машин вне домена

Если ноутбук не в домене или на нём ещё нет Windows, откройте [Библиотека → USB-носители](/usb):

1. Выберите подготовленный профиль Windows (используется его `boot.wim` с WinPE).
2. Выберите загрузчик флешки: **PCA 2011** (для большинства существующих машин) или **UEFI CA 2023** (для новых машин, где в `db` оставлен только сертификат 2023 года).
3. Скачайте собранный архив `omb-uefica-<профиль>-<2011|2023>.zip` (~600 МБ) и распакуйте его в корень обычной FAT32-флешки.

При загрузке с флешки запускается минимальный WinPE со скриптом на VBScript, который определяет производителя (Lenovo, Dell, HP), при необходимости запрашивает пароль BIOS и включает сторонний Microsoft UEFI CA без автоматической перезагрузки (после завершения на экране остаётся отчёт с кодом `20`/`10`/`2`/`3`/`1`).
