Раздел [Библиотека → Скрипты установки](/answers) объединяет файлы ответов для Windows (`autounattend.xml`) и Ubuntu (`user-data`). Сценарии не привязаны жёстко к конкретному ISO — один проверенный файл ответов можно использовать сразу с несколькими образами.

## Конструктор `autounattend.xml` для Windows

В OMB встроен Go-порт `cschneegans/unattend-generator` (`internal/unattend`), работающий полностью офлайн. Он доступен по кнопке «Добавить скрипт… → Создать в редакторе» на странице `/answers`:

- **12 тематических разделов:** язык и раскладки, редакция и ключ продукта, разметка дисков, учётные записи, обход требований Windows 11 (TPM/Secure Boot/RAM при необходимости), параметры OOBE, настройка Проводника и панели задач, удаление встроенных приложений, Wi-Fi, пользовательские скрипты.
- **3 готовых пресета** для быстрого старта (например, базовый корпоративный или лабораторный профиль).
- **Импорт чужих XML:** можно загрузить существующий `autounattend.xml` (до 1 МБ). Незнакомые теги не теряются — редактор переносит их в секцию «Свой XML», а параметры конструктора сохраняются внутри самого XML в элементе `<Editor xmlns="urn:omb:unattend-editor" version="1">`.
- **Режим «Стереть диск и разметить автоматически»:** для сетевой установки WinPE OMB генерирует вспомогательный `pe.cmd`, подключает папку профиля на `I:` и передаёт разметку в `setup.exe`. Такие скрипты помечаются в таблице явной меткой **«стирает диск»**, чтобы оператор не выбрал их случайно.

> [!WARNING]
> Файл ответов с автоматической разметкой уничтожает все разделы на целевом диске без дополнительного подтверждения. Перед публикацией в общее меню обязательно проверьте метку «стирает диск» и испытайте сценарий на тестовой машине.

## Проверка совместимости с образом Windows

При создании или редактировании загрузки в [Библиотека → Загрузки](/installations) OMB выполняет трёхуровневую проверку выбранного XML против метаданных `install.wim` образа:

1. **Архитектура:** соответствие процессора (`amd64`).
2. **Редакция и индекс образа:** наличие указанного в XML имени/индекса редакции (например, `Windows 11 Pro`) среди редакций конкретного `install.wim`.
3. **Семейство ОС и разметка:** предупреждения о потенциальных конфликтах (например, попытка применить сценарий с удалением разделов или несовпадающим языком).

Также при создании загрузки работает автоматическая композиция названия пункта меню вида **«ОС + Скрипт»** с удалением повторяющихся префиксов.

## Учёт ручных проверок сценариев

Технический статус «Готов» означает только то, что XML корректен и сохранён. Чтобы команда знала, какие сценарии реально прошли установку на стенде или железе, в таблице `/answers` есть отдельная колонка **«Проверка»**:

- через меню строки `☰` оператор записывает результат испытания («Успешно» или «Ошибка»), опционально привязывая его к конкретному образу Windows и оставляя комментарий (модель ноутбука, версия BIOS, замечания);
- сохраняется полная история проверок с автором и датой; последняя запись по паре `(скрипт, образ)` определяет текущую отметку.
