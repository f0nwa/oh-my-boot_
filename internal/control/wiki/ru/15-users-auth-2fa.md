Управление доступом сосредоточено в разделах [Система → Пользователи](/users), [Система → Интеграции](/integrations) и [Личный кабинет](/account). Все механизмы аутентификации (LDAPv3, OIDC/JWT, TOTP, QR-кодер в SVG) реализованы внутри OMB без внешних зависимостей.

## Локальные учётные записи и политика паролей

- Логины проверяются по системному стандарту `^[A-Za-z0-9_.-]{3,32}$`; пароли — не короче 12 символов (встроенный генератор паролей использует простые спецсимволы `!@#$%^&*-_+=`).
- В диалоге **«Политика безопасности»** на `/users` задаётся максимальный срок действия пароля (`max_age_days`, `0–3650`) и срок предупреждения (`warn_days`, `0–90`). Для отдельного пользователя в меню `☰` можно выбрать режим «По общей политике», «Бессрочный пароль» или «Свой срок».
- При первом входе, сбросе пароля администратором или истечении срока сессия блокируется и перенаправляет пользователя на изолированную страницу `/change-password` до задания нового пароля.

## Двухфакторная аутентификация (2FA / TOTP)

Для локальных учётных записей доступна 2FA по стандарту RFC 6238 (SHA-1, 6 цифр, шаг 30 с, окно ±1, защита от повторного использования кода и лимит 5 попыток за 5 мин):

- **Политика 2FA** (в «Политике безопасности» на `/users`): `Выключена` (`off`), `Обязательна для администраторов` (`admins`) или `Обязательна для всех` (`all`). Если 2FA обязательна, пользователь при входе попадает на изолированный мастер `/setup-2fa`.
- **Настройка в `/account`:** встроенный QR-код (SVG с издателем `oh my boot_`) и **8 одноразовых резервных кодов** формата `XXXX-XXXX` (хранятся только в виде SHA-256 хешей).
- **Доверенные браузеры:** на шаге подтверждения `/login/2fa` можно отметить чекбокс «Доверять этому браузеру» — сервер выдаст защищённую куку `omb_2fa_trust` (`HttpOnly; Secure; SameSite=Lax`) сроком на 365 дней со скользящим продлением. При следующих входах с этого браузера шаг 2FA пропускается. Количество доверенных браузеров и кнопка их мгновенного сброса находятся в [Личном кабинете](/account); при отключении или сбросе 2FA все доверенные браузеры отзываются автоматически.

## Внешний вход: Active Directory (LDAP) и Keycloak (OIDC)

Настраивается администратором в разделе [Система → Интеграции](/integrations). Секреты интеграций (пароль служебной учётки, client secret) шифруются ключом `/etc/omb/secrets.key` (AES-256-GCM).

### Прямой Active Directory / LDAP

- Работает по **LDAPS** (`:636`) или **StartTLS** (`:389`) со строгой проверкой корпоративного CA.
- Использует служебную учётную запись только для чтения, идентифицирует пользователей по неизменяемому `objectGUID` и поддерживает вложенные группы AD (`1.2.840.113556.1.4.1941`).
- Внешняя учётная запись появляется в `/users` только после первого успешного входа человека с разрешённой группой.

### Внешний Keycloak (OIDC)

- Поддерживает OIDC Discovery, PKCE (`S256`), проверку подписи токенов по JWKS (`RS256`, `ES256`, `ES384`), синхронизацию через Admin REST API, а также RP-Initiated и Back-Channel Logout с защитой от повтора `jti`.

### Безопасность внешних сессий

- **Гибридная проверка прав:** кэш 30 с для обычных просмотров (`GET`) и обязательная живая проверка в AD/Keycloak без кэша на каждое изменяющее действие (`POST`). Если человека отключили в домене или убрали из группы, он мгновенно теряет право на изменения.
- **Локальный SMB/SFTP для внешних пользователей:** раз в 15 мин фоновая проверка отзывает доступ к файловому серверу, если внешняя учётка отключена или лишилась роли.
- **Защита последнего локального администратора:** политика паролей и 2FA применяется только к локальным записям, а удалить или отключить единственного активного локального `admin` невозможно — аварийный вход в панель остаётся доступен даже при падении домена.

## Аварийные консольные команды (`omb` и `omb-controlctl`)

При потере пароля или телефона с 2FA используйте единую утилиту `omb` на сервере (если имя пользователя не указано, по умолчанию выбирается `admin`):

```bash
# Сбросить пароль локального пользователя (по умолчанию admin)
sudo omb reset-password [username]

# Сбросить 2FA и отозвать все доверенные браузеры пользователя
sudo omb reset-2fa [username]
```

Для создания дополнительного локального администратора или низкоуровневых операций также доступна утилита `omb-controlctl`:

```bash
# Создать нового локального администратора (пароль передаётся через stdin)
sudo -u omb-control omb-controlctl create-admin -username recovery-admin

# Сбросить пароль локального пользователя напрямую через omb-controlctl
sudo -u omb-control omb-controlctl reset-password -username admin

# Сбросить 2FA и все доверенные браузеры пользователя напрямую через omb-controlctl
sudo -u omb-control omb-controlctl reset-2fa -username admin
```
