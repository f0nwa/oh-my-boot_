# Ubuntu Desktop: сетевая установка в OMB

[English version](en/ubuntu-desktop-pxe.md). Текущий порядок работы с установками — в [руководстве Control](control-installation.md#ubuntu-autoinstall).

Boot выдаёт один выбранный ISO по `/images/ubuntu-desktop.iso`, а ядро и initrd из него — по `/assets/ubuntu/`. Содержимое остальных ISO хранилища через этот маршрут не публикуется. Несколько установок Ubuntu могут использовать общий профиль с разными файлами Autoinstall.

## Подготовка источника

Укажите абсолютный путь к выбранному ISO в `/etc/omb/boot.env`:

~~~ini
OMB_BOOT_UBUNTU_ISO=/var/lib/omb-images/iso/ubuntu-desktop-amd64.iso
~~~

Это пример пути: замените его реально существующим файлом. Boot должен иметь доступ к нему, включая родительские каталоги. Для источника в локальном каталоге Images нужна дополнительная группа `omb-images` в юните Boot. Для SMB сначала настройте управляемое хранилище.

До подготовки источника завершите активные установки и остановите Boot. Из корня актуального дерева OMB выполните под root, заменив путь ISO:

~~~sh
systemctl stop omb-boot.service
scripts/prepare-ubuntu-source.sh --iso /var/lib/omb-images/iso/ubuntu-desktop-amd64.iso --assets /srv/omb/tftp
~~~

Скрипт монтирует ISO только для чтения, копирует ядро, initrd, Ubuntu shim и `casper/install-sources.yaml` в новое дерево `ubuntu/`, затем пишет `manifest.json` с SHA-256 ISO и файлов. Предыдущее дерево сохраняется рядом как `.ubuntu-backup.*`; его путь показан после подготовки. При ошибке прежнее дерево сохраняется или восстанавливается. Если ошибка связана с размонтированием, оставшийся временный каталог указан в журнале выполнения; не удаляйте содержимое активного монтирования.

Boot при запуске сверяет манифест с настроенным ISO, затем контролирует идентичность, размер и mtime файлов. После замены ISO или загрузочных файлов повторите подготовку и перезапустите Boot. Без метаданных ручная загрузка и вариант ответов «Как в ISO» доступны, но выбор конкретного набора приложений отключён. Ошибка метаданных не останавливает остальные функции Boot.

После успешной подготовки:

~~~sh
systemctl start omb-boot.service
~~~

В `/etc/omb/control.env` должен быть доступный клиентам адрес:

~~~ini
OMB_CONTROL_BOOT_BASE_URL=http://10.30.0.10:8080
~~~

После изменения env перезапустите соответствующие службы. При изменении юнита сначала выполните `systemctl daemon-reload`. Проверьте HTTP HEAD загрузочных файлов и диапазонный GET ISO до публикации. Генератор меню вызывает Ubuntu `shim` только на UEFI; BIOS переходит непосредственно к загрузке ядра.

## Установка и Autoinstall

В «Установках» создайте вариант Ubuntu. Без файла ответов загрузка ручная. Для автоматизации создайте или выберите неизменяемый файл в «Библиотека → Файлы ответов → Ubuntu Autoinstall». Доступны интерактивная разметка, полная очистка диска по выбору установщика с предупреждением об удалении данных и очистка только диска с точным серийным номером. Добавьте установку в черновик меню и опубликуйте.

Проверьте получение согласованной пары NoCloud `user-data` и `meta-data` и ожидаемое поведение установщика на одноразовом диске ВМ. Успешная выдача файлов не подтверждает завершение установки ОС. Условия доступа к данным и работу конструктора см. в [руководстве Control](control-installation.md#ubuntu-autoinstall).

## Проверка и восстановление

`casper` загружает ISO в память. Для ранее проверенного ISO размером около 6,5 ГБ использовалась ВМ с 16 ГБ ОЗУ; при 4 ГБ загрузка завершалась `No space left on device`. Объём памяти для другого ISO проверяйте отдельно.

До технического перехода пользователь подтвердил рабочий стол Ubuntu в SeaBIOS и OVMF с Secure Boot и без него. Полный повторный прогон текущей сборки, включая Autoinstall, отложен до завершения основной разработки. Исходные протоколы доступны через [историю проекта](project-history.md).

При неудачной загрузке проверьте память клиента, доступность ISO, соответствие ядра и initrd, журналы Boot и состояние хранилища. Через «Меню → Версии» можно вернуть доступную прежнюю версию; восстановление файлов и баз описано в [руководстве восстановления](recovery.md).
